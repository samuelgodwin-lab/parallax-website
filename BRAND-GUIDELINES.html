Brand Accent

Parallax Blue is one value. It sits at oklch(0.53 0.18 249), which clears WCAG AA both as text on white and beneath white text on an accent fill — 5.16:1 on white, and still 4.87:1 on --surface and 4.58:1 on --surface-raised. It is set at 0.53 rather than 0.55 for exactly that reason: 0.55 passes on pure white but lands at 4.4993:1 on --surface, which is where most section labels actually sit. The lighter --accent-display is reserved for large type, dots and rules, where the 3:1 large-text threshold applies. It must never carry small text.

Accent lightness moves with the ground it sits on. On dark surfaces — hero scrims, stat bands, this document — the accent runs lighter, not darker: 0.55 manages only 4.26:1 on near-black, while 0.70 reaches 7.67:1. Pick the value for the surface, never by habit.

Colour Usage
  • Use Parallax Blue for labels, section markers, links, and CTAs
  • Keep large surfaces white or near-white — the accent earns attention through contrast
  • Use oklch() values in code — they're perceptually uniform and future-safe
  • Apply --accent-muted as background tints behind accent text
  • Check contrast against the darkest surface a colour will sit on, not against white — a value that passes on white can fail on a card
  • Maintain WCAG AA: 4.5:1 for text under 24px, 3:1 for larger
Avoid
  • Large blocks of accent blue as background fills
  • --accent-display on anything under 24px — it reads 3.90:1 and fails AA
  • Drawing a label's text and its background tint from the same value — that pattern caps contrast around 4:1. Darken the text ~15%
  • Introducing additional hues not in this system
  • Using opacity-based text colours not defined as tokens
  • Hex values directly in code — always use the token names

06 // Motion

Motion & Animation

Motion is intentional and architectural — never decorative. Ease-out for all entrances and hover responses. Ease-in-out for layout shifts and state changes. Scroll-reveal for content sections. No bouncing.

07 // Voice

Voice & Tone

How Parallax speaks. Direct, authoritative, specific. We write like someone who has done this at scale. Think Stripe blog, Figma blog — not generic Medium posts. No throat-clearing. Lead with the point.

Direct
No hedging, no preamble, no buzzwords. The first sentence should carry weight. If you cut it and the paragraph still makes sense, cut it.
"Brand that doesn't perform is decoration."
Authoritative
We speak from experience with BMW, Biblica, Sportradar. Reference specific outcomes and real numbers. Vague confidence is not confidence.
"We reduced time-to-conversion by 40%."
Specific
No generic advice. Genuine expertise, not content marketing. Give the reader something they can act on in the next hour.
"Fix the commissioning process and 70% of the drift disappears within two quarters."
Write Like This
  • "We engineer brand systems that perform under pressure."
  • "Your brand should work as hard as your product."
  • "Fix the governance and the drift disappears."
  • "We don't redesign. We rearchitect."
  • "Parallax has built brand systems for BMW, Biblica, and Accenture."
Never Write This
  • "We're passionate about creating beautiful experiences."
  • "Our innovative solutions leverage cutting-edge methodologies."
  • "We'll make your brand pop!"
  • "As a leading agency, we believe design matters."
  • "Let's circle back on the deliverables going forward."

10 // Imagery

Photography & Imagery

When photography is used it should feel architectural — not decorative. Case study images are the primary imagery format. All bento tile images use object-fit: cover with defined aspect ratios.

01
Architecture Over Lifestyle
Product photography, signage in context, environmental brand shots. Not people smiling at laptops. Not stock handshakes. Show the system operating in the real world.
02
Bento Aspect Ratios
Every image has a defined ratio: 16/7 (lead), 7/5, 1/1, 4/5, 3/2. Never crop arbitrarily. Images must look intentional inside their tile. Use object-position to control the focal point.
03
Dark Overlay on Hero
Hero images always use a gradient scrim: linear-gradient(to bottom, transparent 30%, rgba(0,0,0,0.75) 100%). Ensures title legibility regardless of image content.
04
Video via Vimeo
Case study videos are hosted on Vimeo (unlisted) and embedded via iframe. Stored as URL in the CMS — not as file uploads. Video replaces the lead tile in applications and digital sections.
Part Three

The Product System.

How the same foundations apply to application interfaces — the Project Tracker and anything built after it. Denser than the web: more surfaces, smaller type, persistent chrome, and state that has to be legible at a glance. The palette does not change; the density does.

11 // Surfaces

Surface Scale

Marketing pages need two or three surfaces. An application needs six — canvas, chrome, input, hover, raised, pressed. All are near-white and separated by roughly 0.015–0.025 in OKLCH lightness: enough to read as distinct layers, never enough to look grey.

Surface Rules
  • Elevation is a surface step plus a border — not a shadow
  • Hover lifts a row toward white; it never darkens it
  • Shadows only where something genuinely floats: modals, drawers, popovers
  • Keep --text-3 at 0.51 — it holds 4.66:1 even on --bg-active
Avoid
  • Stacking more than two surface steps in one component
  • Dark panels or inverted sections inside the app — the whole product is light
  • Ambient drop shadows to fake depth on static cards
  • Introducing a seventh surface because two look similar — adjust spacing instead

15 // Implementation

Build Notes

Rules and patterns for engineers building on the Parallax system, on web or in product. These are the conventions that keep it coherent as more surfaces are added.

Always
  • Use CSS custom property tokens — never hardcode colour or spacing values
  • Use oklch() for all colour in CSS — it's the authoritative format
  • Apply font-synthesis: none to prevent faux bold/italic
  • Use clamp() for fluid type and spacing — no fixed breakpoints for copy
  • Left-align all headings — centred headings only for pull quotes
  • Add -webkit-font-smoothing: antialiased to body
  • Verify contrast against the darkest surface a colour lands on, not against white
  • Define every token a module references — an undefined var() silently falls back and can ship the wrong theme
Never
  • Introduce border-radius on structural tiles, buttons, or bento cells
  • Add a third typeface — Bricolage + JetBrains only
  • Use animations with bounce or spring easings
  • Centre-align hero or section headings
  • Use hardcoded hex values — always go through the token system
  • Use the accent colour as a large background fill
  • Put var() in an SVG presentation attribute — stroke and fill do not resolve custom properties. Use currentColor or a literal
  • Build a colour by string-concatenating an alpha suffix onto a token
Heading Highlight Syntax (CMS)
  • Wrap the accent word in *asterisks* in any heading field
  • Example: A mark built to *endure.*
  • One highlighted word per heading maximum
  • Prefer the last word or most impactful noun
  • Renders as <em> tag in accent colour
Web / Product Parity
  • Identical: palette, typefaces, easing, zero radius, left-aligned headings
  • Different: density only — web runs --s24 sections and fluid display type; product runs 13px body and 8–12px control padding
  • Product adds surfaces and status on top of the foundation — it never redefines it
  • A second accent hue for product is never the answer; adjust density or surface instead
  • CMS headings mark the accent word with *asterisks*; product headings take no accent word
